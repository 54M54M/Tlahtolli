# CHANGELOG (Frontend)

## [1.3.0] - 2026-04-02 - Language Switch Modal & DB-driven Flag

### Added

- `VariantSelection.vue` — nueva prop `isModal: Boolean` (default `false`) que permite abrir el componente como overlay desde el header sin pasar por el router.
- `VariantSelection.vue` — nuevos emits `close` y `language-selected` usados exclusivamente en modo modal; el segundo emite el objeto completo del idioma (con `icon`/`emoji`/`color`) para que el componente padre actualice la UI sin recargar la página.
- `auth.js` — nuevo campo de estado `selectedLangObj: null` que almacena el objeto completo del idioma devuelto por la API (incluyendo `icon`, `emoji`, `color`, `nativeName`).
- `auth.js` — `selectedLangObj` agregado a la lista `persist.paths` para que sobreviva recargas de página.
- `vHeader.vue` — modal de selección de idioma implementado con `<Teleport to="body">` + `v-if`, reemplazando el `createApp` secundario. El modal vive dentro del árbol Vue principal y comparte la instancia de Pinia sin configuración adicional.

### Changed

- `auth.js` — `setLanguage()` ahora asigna `this.selectedLangObj = lang` junto a `selectedLangId` y `selectedLanguage`.
- `auth.js` — `initialize()` ahora también restaura `selectedLangObj` cuando solo se dispone del código de idioma persistido (igual que ya hacía con `selectedLangId`).
- `auth.js` — `logout()` resetea `selectedLangObj` a `null`.
- `vHeader.vue` — `currentLanguageData` computed prioriza `authStore.selectedLangObj` (datos de la BD) sobre `LanguageService` local; este último pasa a ser fallback para sesiones previas.
- `ProgressAside.vue` — `selectedLanguageData` computed adopta la misma estrategia: lee primero `authStore.selectedLangObj`, hace fallback a `LanguageService`.
- `VariantSelection.vue` — `goBack()` emite `close` en modo modal en lugar de hacer `logout` + `router.push('/login')`.
- `VariantSelection.vue` — `confirmSelection()` emite `language-selected` con el objeto del idioma en modo modal en lugar de navegar a `/`.

### Fixed

- **Loop infinito al abrir el selector de idioma desde el header.** `VariantSelection.onMounted` ejecutaba `router.push('/')` cuando el usuario ya tenía idioma seleccionado, lo que activaba el guard del router y volvía a `/select-language` indefinidamente. Con `isModal: true` esa redirección se omite por completo.
- **Flag/icono del idioma no reflejaba el valor de la base de datos.** `vHeader` y `ProgressAside` llamaban únicamente a `LanguageService.getLanguageInfo()`, un servicio local con datos estáticos que podía diferir de lo registrado en la BD. Ahora el icono se lee desde `authStore.selectedLangObj`, populado directamente desde la respuesta de la API.
- **`VariantSelection` montado como app separada no tenía acceso a Pinia.** El `createApp` secundario en `vHeader.openLanguageSelector` no registraba la instancia de Pinia, provocando que `useAuthStore()` dentro de `VariantSelection` fallara silenciosamente o usara un store vacío. Resuelto al migrar al patrón `<Teleport>`.
- **Recarga innecesaria de página al cambiar idioma.** Se eliminó `window.location.reload()` en `vHeader`; el watcher de `authStore.selectedLangId` en `HomeView` y el emit `language-changed` son suficientes para actualizar los niveles reactivamente.

# CHANGELOG (Frontend)

## [1.3.0] - 2026-04-02 - Fix: Navegación y persistencia de idioma seleccionado

### Fixed
- **`VariantSelection.vue`** — `confirmSelection()` ahora usa `window.location.href = '/'` en lugar de `router.push('/')` para evitar race condition entre el estado reactivo de Pinia y el router guard; se agrega `await nextTick()` previo para garantizar que pinia-persist escriba en localStorage antes de navegar.
- **`router/index.js`** — El guard dejó de usar `isNewUser` como fuente de verdad (campo derivado susceptible a desincronización) y ahora evalúa `selectedLanguage` directamente; se eliminó la llamada a `authStore.initialize()` dentro del guard para evitar peticiones HTTP en cada cambio de ruta.
- **`stores/auth.js`** — Se agrega método `setSelectedLanguage(languageIdOrCode)` como alias de `setLanguage()`, aceptando tanto ID numérico como código string, resolviendo el crash silencioso en `vHeader.vue` que llamaba un método inexistente.
- **`stores/auth.js`** — `initialize()` ahora resuelve `selectedLangId` a partir de `selectedLanguage` cuando pinia-persist restauró el código pero no el ID numérico; se agrega early-return para evitar doble inicialización.
- **`HomeView.vue`** — La guarda de `loadLevels()` se mueve antes de `loading.value = true` para evitar loading eterno cuando `selectedLangId` es null; se agrega `watch(() => authStore.selectedLangId)` para disparar `loadLevels()` automáticamente si el ID llega después de que el componente montó (race condition con `initialize()`).

### Changed
- **`router/index.js`** — Regla de redirección desde `/login` simplificada: si hay `selectedLanguage` va a `/`, si no va a `/select-language`.
- **`router/index.js`** — Se reemplaza `authStore.$hydrate()` por lógica directa sobre `selectedLanguage`; el guard es ahora síncrono y determinista.
- **`stores/auth.js`** — `initialize()` ya no modifica `isNewUser`; esa responsabilidad recae en `setLanguage()` y en el guard, separando correctamente las responsabilidades.
